
`Advanced`

推测解码（Speculative Decoding）是一种能显著提升大语言模型（LLM）生成速度、同时不降低回复质量的技术。

<hr>

## 什么是推测解码

推测解码依赖两个模型的协作：

- 一个更大的"主"模型
- 一个更小、更快的"草稿"模型

在生成过程中，草稿模型快速提出候选 token（子词），主模型验证这些 token 的速度比它从头生成要快得多。为保证质量，主模型只接受与它自己会生成的结果相符的 token。在最后一个被接受的草稿 token 之后，主模型总会再额外生成一个 token。

一个模型要被用作草稿模型，它必须与主模型拥有相同的"词表"。

## 如何启用推测解码

在 `Power User` 模式或更高级别下，加载一个模型，然后在聊天侧栏的 `推测解码` 区域中选择一个 `草稿模型`：

### 寻找兼容的草稿模型

打开下拉菜单时，你可能会看到以下提示：

<img src="/assets/marketing/docs/speculative-decoding-no-compatible.png" style="width:40%; margin-top: 20px; border: 1px solid rgba(0,0,0,0.2);" data-caption="没有兼容的草稿模型">

试着下载你所加载模型的更低参数量变体（如果有的话）。如果不存在你模型的小尺寸版本，请寻找一组可配对的模型。

例如：

<center style="margin: 20px;">

|          主模型          |          草稿模型          |
| :--------------------------: | :---------------------------: |
|    Llama 3.1 8B Instruct     |     Llama 3.2 1B Instruct     |
|    Qwen 2.5 14B Instruct     |    Qwen 2.5 0.5B Instruct     |
| DeepSeek R1 Distill Qwen 32B | DeepSeek R1 Distill Qwen 1.5B |

</center>

一旦你同时加载了主模型和草稿模型，只需开始聊天即可启用推测解码。

## 影响性能的关键因素

推测解码的加速效果通常取决于两点：

1. _草稿模型_ 相对于 _主模型_ 有多小、多快
2. 草稿模型能够给出"好"建议的频率有多高

简单来说，你要选择一个比主模型小得多的草稿模型。而且某些提示词的效果会比其他更好。

### 一个重要的取舍

在主模型之外运行草稿模型以启用推测解码，需要比单独运行主模型更多的**计算和资源**。

让主模型生成更快的关键，是选择一个既小、能力又足够的草稿模型。

以下是根据主模型规模（以参数量计），你应当选择的草稿模型**最大**规模的通用指南：

<center style="margin: 20px;">

| 主模型规模 | 预期可获得加速的草稿模型最大规模 |
| :-------------: | :--------------------------------------: |
|       3B        |                    -                     |
|       7B        |                    1B                    |
|       14B       |                    3B                    |
|       32B       |                    7B                    |

</center>

一般来说，主模型与草稿模型之间的规模差距越大，加速效果越好。

注意：如果草稿模型不够快，或者向主模型给出"好"建议的能力不足，生成速度不会提升，甚至可能下降。

### 依赖提示词

使用推测解码时，你很可能会注意到：生成速度并非在所有提示词上都保持一致。

之所以加速效果在不同提示词间不一致，是因为对某些提示词而言，草稿模型较难向主模型给出"好"的建议。

以下是一些极端示例，用以说明这一概念：

#### 1. 确定性示例：数学问题

提示词："一元二次方程的求根公式是什么？"

在这种情况下，70B 模型和 0.5B 模型都非常可能给出标准公式 `x = (-b ± √(b² - 4ac))/(2a)`。因此，如果草稿模型把这套公式作为后续 token 提出，目标模型很可能会接受它，使这成为推测解码高效运作的理想场景。

#### 2. 创造性示例：故事生成

提示词："写一个以'门吱呀一声开了……' 开头的故事"

在这种情况下，小模型提出的草稿 token 更常被大模型拒绝，因为每一个后续的词都可能分叉出无数种合理的可能。

虽然"2+2"的唯一合理答案是"4"，但这个故事可以接着"露出一只怪物"、"狂风呼啸"、"莎拉僵在原地"，或者数百种其他完全合理的走向，使小模型对具体词语的预测与更大模型的选词相符的概率大大降低。
