
你可以把文档文件（`.docx`、`.pdf`、`.txt`）附加到 LM Studio 中的聊天会话。

这将为你在应用中聊天的 LLM 提供额外的上下文。

<hr>

## 术语

- **检索（Retrieval）**：从一份很长的源文档中识别出相关部分
- **查询（Query）**：检索操作的输入
- **RAG**：检索增强生成（Retrieval-Augmented Generation）\*
- **上下文（Context）**：LLM 的"工作记忆"。有最大容量限制

###### \* 在此语境中，"生成（Generation）"指 LLM 的输出。

###### 上下文容量以"token"计量。一个 token 通常约为 3/4 个单词。

## RAG 与"整篇文档放入上下文"

如果文档足够短（即能放进模型的上下文），LM Studio 会把文件内容完整加入对话。这对支持较长上下文的模型（如 Meta 的 Llama 3.1 和 Mistral Nemo）尤其有用。

如果文档非常长，LM Studio 会选择使用"检索增强生成"，通常简称"RAG"。RAG 意味着尝试从一份（或多份）很长的文档中捞出相关片段，并把它们提供给模型作为参考。这种技术有时效果非常好，但有时需要一些调优和试验。

## 成功使用 RAG 的技巧

在你的查询中提供尽可能多的上下文。提及你预期会出现在相关源材料中的术语、概念和词语。这通常会提高系统为 LLM 提供有用上下文的几率。一如既往，试验是找到最佳方式的最好途径。
